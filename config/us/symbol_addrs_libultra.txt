// libultra functions this ROM contains, and only those.
//
// N64Recomp decides what to hand to N64ModernRuntime **by name**. A function
// whose symbol is `osAiSetFrequency` is on its reimplemented list and its ROM
// body is dropped in favour of the runtime's; the same bytes under the name
// `func_8004F540` are recompiled instruction by instruction, and then either
// fault at run time (a memory-mapped access is translated by the MEM_* macros
// into an offset from rdram and lands past the end of the 8 MB allocation) or
// fail the build outright (a COP0 access has no MEM_* form at all, and
// N64Recomp models exactly one COP0 register, Status).
//
// These entries were derived by reading each function, not copied from another
// project's map. For this class of function the name is not a judgement call:
// the hardware block it addresses and the width of the access are the identity.
// `lui 0xA450; lw 4(rX)` is a read of AI_LEN and can only be osAiGetLength;
// `mtc0 r4, cop0[11]` can only be __osSetCompare. tools/find_hardware_funcs.py
// prints the fingerprint of every function that touches hardware, and
// tools/check_libultra_names.py checks each name against the vocabulary
// N64Recomp actually implements -- a correct name it does not know buys nothing.
//
// Entries are deliberately omitted where they would not help: hardware-touching
// functions that N64Recomp has no implementation for stay unnamed here and are
// listed as work in the README, because renaming them would change nothing and
// the port has to replace them instead.

// --- COP0 ------------------------------------------------------------------
// N64Recomp models COP0 register 12 (Status) only; everything else here is a
// build failure until the function is named.

// --- Parallel interface (0xA460) -------------------------------------------
// osPiStartDma is the one that mattered. It is the high-level entry point the
// boot path waits on, and it was left unnamed here at first, so its ROM body was

// message the caller was blocked on never arrived, and the port booted to a black

// --- SDK routines the host already implements -------------------------------
// A second reason to name a function, and the more important one. N64Recomp
// hands a function to the host *by name*, and the host already has an
// implementation for each of these: either the runtime's libultra translation
// or this port's own shims (port/src/replaced_funcs.cpp). Naming them drops the
// ROM body from recompilation and routes every caller to that implementation.
//
// Leaving one unnamed is not neutral, because the rule cuts both ways. A
// recompiled body calls its callees, and when a callee is an SDK routine the
// call is renamed to `X_recomp` -- so an unnamed *caller* of a named function is
// a link error, not a silent fallback. That is what this list exists to settle:
// name every function the host implements, and leave unnamed every function it
// does not, because a name with no implementation behind it only moves the
// failure. tools/find_hardware_funcs.py reports the hardware end of this;
// tools/check_libultra_names.py reports whether a name has anything behind it.
//
// The addresses were read, not assumed. osSpTaskLoad sets SP_STATUS, sets the
// RSP PC to 0x4001000 with a retry loop around each write, and DMAs the 0x40-byte
// task copy to DMEM 0xFC0 and the microcode text to IMEM 0x1000 -- which is also
// what port/src/main.cpp reasons about, in its comment on the audio command
// window. __osTimerInterrupt walks the timer queue at D_8007B300 and, when it
// empties, zeroes COMPARE and the time base at D_800856F0.
//
